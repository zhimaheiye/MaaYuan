## 作业生成入口与目标语义

本机通用入口为 `.agents/skills/maayuan-copilot-builder/SKILL.md`，其编译器、坐标档位和示例于 2026-11-15 从智能圈工作树复制到主工作区。它是通用作业生成技能，不要求切换到智能圈分支。功能分支中可回读的[技能快照](https://github.com/zhimaheiye/MaaYuan/blob/f5e91978f38cdc7e4aa3487d77701d40589a1670/.agents/skills/maayuan-copilot-builder/SKILL.md)为较早版本，不能代替本机 `1.12.0` 的全部指导。

2026-11-17 的技能修订来自一次明确的生成错误：Agent 把格内颜色表示的攻击目标降成“仅记录的阶段备注”，用户已经说明红色为 BOSS 右一、紫色为右二后，仍没有插入左右操作。还一度准备把其他关卡的 OCR 搜索方案套过来。

应保留的决策是：颜色和左右位置是输入语义，已知当前目标时应翻译为已有 `target_left` / `target_right` 动作，而非要求攻略额外写出 Q/E。譬如 BOSS 到右一只需右移一次，`2EA` 可表达第 2 动先右移再普攻；同格不同动作要分别读颜色。角色列、行动序号和敌方位置须分开。技能已包含详细规则，本次不重复完整编译规范。

静态切换并不意味着可以无条件累计目标位置：在安期作业的历史实机现场，旧作业第三回合左移两次实际选到了星剑，而不是预期 BOSS。该关后来采用逐动作读敌名的方案，第三回合前三动实际确认打 BOSS；完整 23 回合未在本对话中验证。该方案针对当时的目标漂移，不能推广为所有作业都必须 OCR 搜索。另一关的已归档实机方案见[金乌枝一七回合作业的识别与重试](金乌枝一七回合作业的识别与重试.md)。

安期攻略的回合展开也已明确：实际 18、19 回合重复原表 16、17；实际 20～23 回合对应原表 18～21，游戏回合号始终递增。仅为这份作业重复一次，不把它推广成无限循环或回合倒退。

## 智能圈的维护入口与已验证边界

智能圈的正式 Git 证据从功能提交 `b9fab75a83e45b9ce8234c4c64e9bcef1508da6e` 可追踪到上述 `f5e91978`，后者增加了单人录屏作业。两者之间两个智能圈 Python 模块和 `dragon_smart.json` 没有变化。完整策略、分支参数、能量识别限制、用户反馈及两份作业用法见功能分支的[维护说明](https://github.com/zhimaheiye/MaaYuan/blob/f5e91978f38cdc7e4aa3487d77701d40589a1670/tools/copilot/dragon_smart/README.md)和[智能圈说明](https://github.com/zhimaheiye/MaaYuan/blob/f5e91978f38cdc7e4aa3487d77701d40589a1670/.agents/skills/maayuan-copilot-builder/references/zhugeliang_smart_circle.md)。

关键设计原因是：吕布的“圈”点击专属形态按钮；诸葛亮的“圈”按龙脉、龙气、技能能量选择普通动作。早期“检测到 2 龙气就下拉、否则上滑”不足以处理龙脉外无技能等情况，不能作为兼容回退重新启用。具体攻略可重映射分支，日志应报告实际转入的动作，不能把内部 `defense` 分类直接当成必然下拉。

历史现场曾因动态 Boss、衣袖干扰而调整稳定性区域。当前功能分支和本机配置使用 720×1280 原图底部两块区域 `[0,1220,220,55]`、`[440,1220,275,55]`；它们是该版布局中卡牌下方露出的背景，不是适用于任意桌面截图的“卡牌下面”。模板变体属于同一位置，不能重复计票；桌面截图的缩放和裁边不能当作模拟器原始坐标。

2026-11-02 用户对 10 回合观察作业反馈无问题，功能分支维护说明已有记录；这不是跨敌人、所有状态或沉默等技能限制的全面验收。单人作业只需生成 1 号位动作，但画面识别仍可能受空卡位影响，不能仅靠 JSON 只有一个角色就宣称视觉兼容。
