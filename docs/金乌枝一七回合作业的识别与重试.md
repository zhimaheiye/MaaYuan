# 金乌枝一七回合作业的识别与重试

这份本地作业解决两个独立问题：每回合要赌指定星色，最后吕布要打美人鱼，但木桶可能还在。即使七个星色全部符合，也可能战败。因此，星色决定本回合是否继续，胜负由战斗结算单独判断。

## 作业入口与重试条件

本机缓存文件是 `install/resource/copilot-cache/自定义-遗迹1-7回合-唤星失败重试.json`。从如鸢主城第二页进 **地宫 → 地下遗迹入口 → 金乌枝1 → 进入战斗**。到编队页后，在 MaaYuan 激活这个完整文件名，从第 1 回合开始抄，关闭“战斗中开始抄作业”和“抄作业胜利后继续”。已进入战斗且第 1 回合尚未行动时，可展开手动/倍速面板，从战斗中启动。本机冷启动路线和已选 MuMu 主实例见个人技能 `ruyuan-jinwu-retry`。

| 识别结果 | 七回合版的行为 |
| --- | --- |
| 本回合星色符合蓝、蓝、紫、橙、蓝、紫、橙 | 继续本回合。星光闪烁时蓝色区域可能仅有几个像素，本作业保留原色域，最低匹配数为 1，间隔 350 ms 再确认同色。 |
| 确认错色，或进入第 8 回合仍未胜利 | 撤退，核对地下遗迹地图、金乌枝1详情与编队，再从第 1 回合开始。 |
| 战败，出现“再次挑战” | 点击后按实际到达的页面接回同一关，不限制重试次数。 |
| 确认胜利 | 结束作业。玩家也可以在客户端手动停止。 |
| 敌名或导航页持续无法识别 | 停止并保留现场，检查最后命中的节点。 |

## 木桶存亡如何影响切目标

31 个动作都先读取居中敌人的名字。按短边 720 的竖屏，OCR 区域为 `[260,170,180,60]`，阈值 0.85，精确匹配陈登、木桶或美人鱼。已是所需敌人就执行当前动作；否则由读到的名字决定左右方向，切一次后重新读名。每次找目标最多切两次，次数随动作重新开始。两次后仍明确读到其他敌人就撤退重试。

攻略颜色随**动作**走。第 1 回合兄妹第 3 动下拉前就要选木桶。第 7 回合前三动选陈登，吕布第 4 动切形态前选美人鱼，第 5 动放技能前再确认一次。这样木桶已退场时，第一次就读到美人鱼即可出手；木桶仍在时，可以再切一次。

## 资源加载和开局即停的排查

- 缓存文件保存完整作业，客户端激活后加载的是 `resource/base/pipeline/copilot/` 下的裸动作节点。基础包已有准备开战、胜利和结束等节点；需要自定义转移时起专名，并检查完整资源包。只对内存执行 `override_pipeline` 无法复现两个文件声明同名节点的加载错误。
- 若已进入战斗、任务却在第 1 动前结束，检查 [起始回合选项](../assets/interface.json) 对 `检测回合N` 的覆盖。该选项用侧边按钮上的“手”或“情”判断战斗界面，只覆盖 OCR 预期文字和区域。作业残留的数字模型 `model: "en"` 和 `only_rec: true` 会妨碍读中文。本作业使用默认中文模型并允许文字检测。用“当前：第1回合”之后的星色与动作日志确认开局成功。
